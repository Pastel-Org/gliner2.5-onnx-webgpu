GLiNER2 vs 2.5, and what this page can run

GLiNER2 enumerates candidate spans up to a fixed width (about twelve words). Anything longer is invisible. GLiNER2.5 scores start and end boundaries instead, so a forty-word clause costs the same as a two-word name, and the public 4k-word window plus library chunking covers full documents.

Fastino's 2.5 blog also adds JointIE knowledge graphs, constrained classification, and span attributes. Those extra heads are in the Python library. This ONNX graph is the boundary entity path: [E] queries, pair reranker, char-offset spans. Structure fields work because they are the same [E] queries under a different parent name. Document classification ([C]) and typed relations ([R] / JointIE beam search) do not.

CrossNER is the one public NER number we can check. Fastino reports macro F1 on 2.5-base 58.30 / 2.5-multi 54.85. Our JS ONNX v2 domain-macro (same five test splits, threshold 0.5) is 55.8 / 52.2. JS matches Python AutoExtractor on those splits; the remaining ~2.5 points is protocol (token-level vs char-span, not the export). Classification tables (XNLI +24.75, IMDB, …) cannot be reproduced from this graph.
